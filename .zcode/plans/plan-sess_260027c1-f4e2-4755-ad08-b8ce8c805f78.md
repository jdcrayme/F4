# Textured Terrain + Unified World Load/Render Path

Verified on disk: the Steam install (`D:/SteamLibrary/steamapps/common/Falcon 4.0`) has everything needed — `THEATER.L0–L5` + `O0–O5` (sizes validate exactly as 7-byte `TdiskPost` blocks with O-file offset dedup: L0=256×256 blocks … L5=8×8=128×128 posts), `FArtILES.PAL/.RAW` (53,400 far tiles, 32×32, 8-bit + shared 256-entry palette), `TEXTURE.BIN` (near-tile set DB), `texture.zip` (near-tile art). FreeFalcon (`src/graphics/terrain/*`, `terrtex.cpp`, `fartex.cpp`, `otwdraw.cpp`) is the format/rendering reference. Key anchor: **L5's 128×128 posts map 1:1 onto the MEA 128×128 grid**, so the post system calibrates onto the existing ENU convention without touching world coordinates.

## Phase 1 — f4-terrain: decode posts & tile databases

New binary-loading code in `f4-terrain` (runtime reads binaries directly; `terrain.json` stays the summary/interchange format — 74 MB of posts never goes through JSON):

1. **`TheaterGeometry`** — single source of truth for ENU↔post↔block↔MEA-cell conversion (post spacing per level = theater_ft / (blocks_wide×16), blocks_wide from √(O-file size/4)). Replaces the 4 duplicated sampler helpers (`terrain_mesh.cpp:42,62`, `terrain_chunks.cpp:40,46`, `ground_layout_3d.cpp:349-364`). Keeps the repo's 1,048,576 ft theater convention for now (true Korea is 3,358,720 ft per FTtoMEAcell) — one documented constant so it can be corrected later without disturbing world coords.
2. **`PostLevel`** — parses `THEATER.O<N>` (u32 block-offset table) + `THEATER.L<N>` (`TdiskPost{u16 texID; i16 z; u8 color; u8 theta; u8 phi}`, 256 posts/block, row-major from SW corner). API: load-by-level (whole file; L1≈15 MB/L2≈4 MB fine), `post(col,row)`, `elevation_at_ft()`, `texid_at_ft()`. Also decode theta/phi normals (azimuth 0..255→0..2π, elevation 0..63→0..π/2) for later shader use.
3. **`FarTileDB`** — `FArtILES.PAL` (256×4 palette + trailing u32 counts) + `FArtILES.RAW` (N×32×32 indices). API: `tile_rgba(index)`.
4. **`NearTileDB`** — parses `TEXTURE.BIN` (sets, 20-char filenames, per-set terrainType, TexArea/TexPath records — parsed, unused in v1); texID unpack `set=(id>>4)&0xFF, tile=id&0xF, res=(id>>12)&0xF`. Lazy art loading from `texture.zip` (reuse/extract the zip reader from f4-world-convert's CamArchive into f4-io) or loose files; 8-bit palettized TGA via raylib `LoadImageFromMemory`, custom decoder fallback (precedent: `tex_reader.cpp`); H/M/L resolution families by first-char prefix rewrite; per-set palette from first tile loaded.
5. **Tests** — small synthetic fixtures committed; env-gated tests against the real install (`F4_INSTALL` CMake var already exists).

## Phase 2 — f4-renderer: textured terrain chunks (both apps benefit immediately)

6. **`TerrainTileCache`** (GPU) — lazily uploads referenced tiles into growing `GL_TEXTURE_2D_ARRAY` pages (RGBA8; separate array per tile-size family: far 32×32, near per discovered size). Fallback if arrays fight raylib: padded atlas with baked UVs.
7. **`TerrainShader`** (modeled on `LitShader`, GLSL 330) — tile layer index carried in `vertexTexCoord2.x` (standard raylib attribute set); fragment samples the array × ambient/N·L lighting (same uniforms as lit shader) + distance fog toward sky color.
8. **Chunk builder v2** (`terrain_chunks.cpp`) — when tile data present: per-quad vertices (4 verts/quad), elevation from `PostLevel` at the view's LOD (MEA-bilinear fallback), texID from post, UVs ported verbatim from FreeFalcon's `DiskblockToMemblock` math (tile spans 4 posts at near LODs, full-tile step at the near/far boundary), tile→cache upload→layer index. Untextured vertex-color mode kept as fallback (JSON-only terrain loads).
9. **LOD policy v1** — inner near-textured region (L1/L2) + outer far-textured region (L4/L5) around the view origin, simple overlap/skirt at the seam. FreeFalcon's full ring/connector OTW system is explicitly out of scope (future work).
10. `SceneDescription`/`render_world()` signature unchanged — chunk draw switches to TerrainShader + tile arrays.

## Phase 3 — Unified WorldView: one load-a-world → render-a-view API

11. **`f4::renderer::WorldView`** (new; f4-renderer gains dep on f4-world for `populate_world`) — owns the lifecycle both apps hand-roll today:
    - `load_theater(theater_dir)` — TerrainData + PostLevels + FarTileDB + NearTileDB, graceful degradation to untextured.
    - `attach_world(world_json, ...)` — WorldState::load + `populate_world` + ModelDatabase/ClassTable (world-viewer path; scenario-player may skip).
    - `set_view_origin(east_ft, north_ft)` — throttled rebuild of textured chunks around origin.
    - `update(camera)` / `populate_scene(SceneDescription&)` — fills terrain/model/class-table fields; app fills camera, entities, overlays. `render_world()` stays the single draw entry. Owns unload before GL teardown.
12. **Migrate both apps** onto WorldView and delete the duplicated code: scenario-player mesh-build block (`player_app.cpp:166-182`), world-viewer 3D-tab terrain block (`ground_layout_3d.cpp:487-546`), the sampler-helper copies, the inline elevation sampling. Scenario JSON gains optional `theater_dir` (via `@F4_TERRAIN_DIR@` configure substitution, same pattern as existing `.json.in` scenarios).

14. **Diagnostics** — extend the diagnostics panel with tile DB stats (sets/tiles loaded, array layers, chunk counts).

## Risks / notes
- **Theater scale**: repo convention (1,048,576 ft) vs true (3,358,720 ft) — kept internally consistent via TheaterGeometry; correcting it is a separate follow-up.
- Per-set palettes ("first tile wins") can miscolor near art — validate visually against FreeFalcon screenshots.
- `vertexTexCoord2` in a custom raylib shader must be verified early (rlgl uploads it when the mesh has it); atlas-UV fallback exists.
- `FArtILES` casing and `texture.zip`-packed art are stock-install quirks the parsers must tolerate.

Execution order: Phase 1 → 2 → 3 → 4, each phase leaving both apps buildable and shippable.
