Part I — Campaign System

Dynamic campaign mission generation, tasking, PAK management, supply/logistics, squadron rotation, weather, and victory point scoring.

Falcon 4 Dynamic Campaign — Mission Generation Logic

1. Architectural Overview

The system uses a request → queue → fulfill pipeline built on a VU (Virtual Universe) distributed entity framework. Campaign entities (Squadrons, Flights, Packages, Objectives) are all VU entities with network IDs, ownership, and serialization. The pipeline has three distinct layers:

  1. Request Generators — Various campaign subsystems (strategy, tactics, objectives, event triggers, player calls) create MissionRequestClass messages and send them to the team's Air Tasking Manager.
  2. Air Tasking Manager (ATM) — The central arbiter. Receives requests, sorts them by priority, deconflicts, and attempts to fulfill each by building a Package.
  3. Package/Flight Builders — PackageClass::BuildPackage() selects squadrons, creates flights, generates threat-avoiding routes, assigns loadouts, and assembles multi-flight packages with escorts, SEAD, and support.

The campaign runs on a separate thread (CampaignThread). A master CampaignClass object tracks time (CurrentTime) and controls when each domain's tasking and planning cycles fire by comparing timestamps like lastAirTask, lastAirPlan, etc. against the current campaign time.

Entity hierarchy:


FalconEntity (VU entity)
  → CampManagerClass (base for all tasking managers)
    → AirTaskingManagerClass
    → GroundTaskingManagerClass
    → NavalTaskingManagerClass
  → UnitClass → AirUnitClass
    → SquadronClass
    → PackageClass
    → FlightClass

4. Mission Request Creation

4.1 Entry Point — RequestMission()

The standard path for mission requests. Creates a FalconMissionRequestMessage, calls GetPriority() to compute a final priority value, and sends it to the team's ATM. If priority ≤ 0, the request is silently dropped.

4.2 Key Request Generators

ATM::DoCalculations() (auto-generation each cycle):

  • For each active friendly airbase: generates an AMIS_OCASTRIKE against it with priority = usage × 30, TOT 30–90 minutes in the future
  • For each carrier: generates AMIS_ASHIP missions
  • Cycles through supply bases generating AMIS_AIRLIFT missions (one per base per cycle)
  • Updates AWACS/JSTAR/Tanker/ECM location lists

RequestIntercept() — Creates an AMIS_INTERCEPT with AMIS_IMMEDIATE flag when AWACS detects incoming strike-type enemy aircraft. Stores the enemy's heading and the entire enemy package's air combat score as match_strength.

RequestSARMission() — Creates AMIS_SAR at a downed aircraft's location. Refuses if DistanceToFront > MAX_SAR_DIST.

TargetAllSites() — Batch-generates requests for all objectives within a primary objective's area:

  • Airbases/Strips/Army Bases → AMIS_OCASTRIKE at TOT+15 min
  • C3 Facilities → AMIS_STRIKE at TOT+15 min
  • Radar sites → AMIS_OCASTRIKE targeting the radar feature specifically
  • Factories/Depots/Refineries/Ports/Powerplants → AMIS_INTSTRIKE at TOT+25 min
  • Bridges → AMIS_INTSTRIKE at TOT+25 min
  • Air defense units → AMIS_SEADSTRIKE at TOT+5 min
  • Also generates 3 sweep missions at TOT+5, +15, +25 minutes

4.3 Mission Context System

Each request carries a mission_context code (~60+ options) describing why the mission was requested: enemyUnitAdvanceBridge, attackEnemyUnit, enemyStrikesExpected, interceptEnemyAircraft, friendlyRescueExpected, enemySupplyInterdictionBridge, enemyProductionSource, enemyAirDefense, AirActionPrepAD, AirActionPrepAB, AirActionOCA, AirActionInterdiction, AirActionCAS, etc. This context feeds into the priority calculation.

5. Request Processing and Prioritization

5.1 ProcessRequest() — Queue Insertion

When a request arrives, the ATM:

  1. Adjusts target location for support missions — snaps to nearest AWACS/ECM/Tanker orbit track
  2. Adjusts priority:
  • REQF_PART_OF_ACTION: priority += 100 (capped at 255)
  • Not part of action: priority -= 25 (floored at 0)
  1. Handles unspotted targets:
  • Objective targets: 20% chance → converted to AMIS_RECON (priority ÷ 4); 20% chance → dropped entirely
  • Unit targets: 33% chance → converted to AMIS_SAD
  • Naval targets: 66% chance → converted to AMIS_PATROL (priority ÷ 4)
  1. Deconflicts against both active packages and queued requests — if same mission type + same target + within mintime and mindistance → drops the duplicate
  2. Inserts into the priority-sorted requestList (sorted linked list, highest priority = last element)

5.2 Mission Filling Budget

missionsToFill limits how many non-essential missions are planned per cycle. It's incremented probabilistically when RequestMission() is called based on actionTempo. The missionsFilled counter resets each cycle.

6. The Main Tasking Cycle — ATM::Task()

Called once per campaign update cycle. This is the heart of mission generation.

6.1 Execution Flow


1. Guards: check team is active, local, has squadrons
2. Check flags: if neither ATM_NEW_REQUESTS nor ATM_NEW_PLANES set → return
3. Clear ATM_NEW_PLANES flag
4. For non-final packages: call Package::CheckNeedRequests() (generates sub-requests)
5. Iterate requestList from HIGHEST to LOWEST priority:
   a. Skip if missionsFilled >= missionsToFill (unless action mission or FLYALWAYS)
   b. If AMIS_IMMEDIATE → BuildDivert()
   c. Otherwise → BuildPackage()
   d. Clamp aircraft count to MissionData[].str
   e. Handle result:
      - PRET_SUCCESS → insert into packageList
      - PRET_DELAYED → move to delayedList (retry next cycle)
      - PRET_TIMEOUT → delete request permanently
      - Other → delete request
6. TIME BUDGET: return after 200ms of processing
7. Clear ATM_NEW_REQUESTS, move delayedList back to requestList

6.2 Time Budget

The ATM has a 200ms processing budget per Task() call (GetTickCount() - task_time > 200). This prevents the campaign thread from stalling. If the budget expires mid-iteration, remaining requests wait for the next cycle.

7. Package Building — BuildPackage() → PackageClass::BuildPackage()

7.1 Target Analysis

  1. Sets destination from the request
  2. Initializes package_flags from MissionData[].flags
  3. For objective targets with multiple features: iteratively selects up to 5 targets / 4 flights using BestTargetFeature(), preferring different feature types. Stops when objective status reaches 0%.
  4. Priority gating: If priority > 150 (ATM_HIGH_PRIORITY), forces at least 2 strike flights.

7.2 Threat Assessment

  1. Calls ScoreThreatFast() at min and max altitude to get low-alt and high-alt threat scores
  2. If either exceeds MIN_SEADESCORT_THREAT → sets NEED_SEAD bit
  3. If priority > 150 and both altitudes have nonzero threat → forces NEED_SEAD
  4. Cancellation: If threat at BOTH altitudes exceeds MAX_FLYMISSION_HIGHTHREAT → returns PRET_CANCELED. If it exceeds MAX_FLYMISSION_THREAT → triggers CallInOCAStrikes() (enemy OCA response) and cancels.

7.3 Main Strike Flight Creation

For each target:

  1. Calls AttachFlight() which either steals an in-flight aircraft (AMIS_IMMEDIATE) or calls FindBestAir() to select a squadron and creates a new Flight entity
  2. Calls flight->BuildMission(mis) to generate the route, timing, and loadout
  3. On the first flight only: extracts ingress/egress waypoints (assembly point, breakpoint, target area) and stores them in the Package for other flights to reference
  4. Bomber conversion: If the squadron's strategic bombing rating exceeds its strike rating (and 75% random), converts mission to AMIS_STRATBOMB

7.4 Support Flight Addition

SEAD Escort (if AMIS_ADDSEAD AND NEED_SEAD detected):

  • Creates AMIS_SEADESCORT flight targeting the main strike flight
  • Aircraft count: min(MissionData[SEADESCORT].str, main_flight_aircraft)
  • TOT offset: MissionData[SEADESCORT].separation × CampaignSeconds

Fighter Escort (if AMIS_ADDESCORT — always added):

  • 50% chance of SEAD escort vs fighter escort (unless escorttype specified)
  • Targets the main strike flight (element[0])

FAC (if AMIS_ADDFAC and exactly 1 flight):

  • Creates AMIS_FAC flight, TOT 5 minutes early, using reserves
  • If no FAC available: converts ONCALLCAS to AMIS_PRPLANCAS or cancels

Enemy Reaction Triggers (the package proactively generates enemy missions):

  • AMIS_ADDBARCAP → sends enemy AMIS_BARCAP request with match_strength = aa_strength, priority = mis->priority / 5
  • AMIS_ADDSWEEP → sends enemy sweep request at random TOT offset ±120 sec

7.5 Support Flight Search — FindSupportFlights()

Searches existing active packages for compatible support:

  • AWACS/JSTAR/ECM/Tanker: Finds closest existing flight that has taken off and will remain on station past mis->tot + (loitertime + 10) × CampaignMinutes
  • Tanker: Prefers proximity to the ingress assembly point over target
  • If no existing support found, creates new mission requests:
- Tanker: priority 50, `REQF_NEEDRESPONSEREQF_ONETRY, sets wait_for= AMIS_ADDTANKER`
  • AWACS: context friendlyAWACSNeeded
  • ECM: only if NEED_ECM bit set, context enemyRadarPresent

7.6 Package Finalization — CheckNeedRequests()

Called each cycle. Manages a wait/timer system:

  1. Decrements wait_cycles each call
  2. When timer expires OR past takeoff deadline:
  • Gives up on pending BARCAP/SWEEP requests
  • If AMIS_ADDBDA and priority > MINIMUM_BDA_PRIORITY: adds BDA flight
  • If tanker needed and g_bTankerWaypoints: inserts tanker waypoints into each flight
  • Finalizes all child flights via FinalizeFlight() — removes unused waypoints, sets assembly coordination
  • Sets SetFinal(1) — package is now locked and active

8. Squadron Selection — FindBestAir()

This is the core squadron-picker, scoring each squadron in the team's list:

8.1 Hard Filters (must pass ALL)

  1. Not relocating: squadronRetaskAt > currentTime → skip
  2. Skill threshold: Base score = (rating[role] + 4) / 5 must exceed (255 - priority) / 25
  3. Specialty match: +5 if squadron specialty matches role (AA or AG), -5 if mismatched
  4. Capability check: (caps & stats) == caps — must have all required capabilities (stealth, night, VTOL, etc.)
  5. Stealth restriction: Stealth aircraft only fly at night (TimeOfDayGeneral(tot) != TOD_NIGHT)
  6. NPC-only filter: AMIS_NPC_ONLY missions skip squadrons with valid player aircraft types
  7. Range check: distance + loiter_distance ≤ squadron_range. Short-range aircraft get loiter reduced to min(45, original)
  8. Speed matching: If AMIS_MATCHSPEED, aircraft max speed must be ≥ required and cruise ≤ 1.2× required
  9. Schedule check: The airbase's 5-minute time block must not be fully occupied (ATM_CYCLE_FULL = 0x1F)
  10. Aircraft availability: FindAvailableAircraft() must return ≥ aircraft - 1 (or ≥ 1 if using reserves)

8.2 Scoring Adjustments

ConditionBonus
Player squadron (priority tier dependent)+1 to +3
Already assigned to this package+3
Same airbase as previous assignment+2
Within half range+2
Same-owner carrier (transport)+5
Insufficient aircraft-5
Quickest arrival time+2

8.3 CA Mission Sizing

If match_strength > 0 and role is ARO_CA: defaults to 4 aircraft; reduces to 2 if the aircraft's HitChance[Air] × 1.5 > match_strength (avoiding overkill).

9. Aircraft Availability and Scheduling

9.1 FindAvailableAircraft()

  1. Computes available pool: max(percentage × totalVehicles / 100, minimum_available) — configurable via g_npercentage_available_aircraft and g_nminimum_available_aircraft
  2. If REQF_USERESERVES: uses ALL vehicles instead
  3. For each time block from start_block to final_block: clears availability for blocks where the schedule bit is set
  4. Returns the number of available aircraft and fills mis->slots[]

9.2 Airbase Schedule System

Each airbase has a uchar schedule[32] array — 32 bytes, each representing a 5-minute time block (160 minutes total). Each bit in a byte represents one minute's runway occupancy (5 bits used per byte, ATM_CYCLE_FULL = 0x1F means all 5 minutes occupied).

FindTakeoffSlot(): Tries the requested slot, then +1, +2 minutes forward, then up to 10 slots backward. Returns 0xFFFFFFFF on failure.

ScheduleAircraft(): Marks takeoff slot and next block. For flights > 2 aircraft: marks an additional slot. For single-runway bases: also schedules landing slots.

ZapAirbase() (damage response):

  • 0 runways: zaps entire schedule for repair duration
  • 1 runway: zaps every other block
  • 2+ runways: no change
  • Cancels all flights planned during zapped blocks

9.3 Pilot Assignment — AssignPilots()

  • Slot 0 (Flight Lead): Scans first third of pilot roster for PILOT_AVAILABLE (commanders)
  • Remaining slots: Scans backward from end of roster (wingmen)
  • If no pilot found for any slot → flight fails

9.4 Rating Decay

After assignment: new_rating = (int)(0.75 × current_rating) + 1 — reduces the squadron's effectiveness rating for that role by ~25% to prevent the same squadron from being picked repeatedly in a single cycle.

10. Route Planning and Waypoint Generation

10.1 BuildPathToTarget() — Master Route Builder

For each flight in a package:

  1. Create takeoff WP at airbase location
  2. Ingress (unless AMIS_TARGET_ONLY):
  • SetupIngressPoints() for the main flight, AddIngressPath() for escorts
  • Creates assembly point and breakpoint
  1. Target area waypoints based on target_profile:
  • TPROF_ATTACK → IP → Target → Turn point (+ Assembly, Breakpoint)
  • TPROF_LOITER/TPROF_SEARCH → Target + looping WPs (racetrack pattern)
  • TPROF_SWEEP → 3 circular turn points forming sweep arc
  • TPROF_FLYBY → single target overflight
  • TPROF_LAND → land + station + takeoff
  • TPROF_HPATTACK/TPROF_TARGET → target only
  • TPROF_AVOID → breakpoint + turn point
  1. Egress: SetupEgressPoints() or AddEgressPath()
  2. Landing WP at home base
  3. High-altitude WP 30 NM before home for long-range missions (>40 NM from base)
  4. Cleanup: EliminateExcessWaypoints() trims unnecessary filler waypoints

10.2 Threat-Avoiding Ingress — SetupIngressPoints()

  1. Creates a temporary WP at the target location
  2. Calls CheckSafePath() — if threat exceeds MIN_AVOID_THREAT:
  • Calls FindSafePath() which uses A* pathfinding with PATH_ENEMYCOST flag
  • The A* extend function GetNeighborCoord() samples ScoreThreatFast() at the cell center and 4 cardinal neighbors (at MAP_RATIO intervals), taking the maximum. If > 120 → cell is impassable
  • Otherwise: cost = base_cost × step + threat_cost / 2.0
  • Heuristic multiplier: Air = 4.0 (encourages finding routes around threats)
  1. Calls AddSafeWaypoint() to find an assembly point at MIN_AP_DISTANCE from target, in friendly territory, outside threat zones, and away from the FLOT
  2. Adds a breakpoint at BREAKPOINT_DISTANCE × 2 before target
  3. Saves assembly/breakpoint locations in the Package for all other flights to share

10.3 Altitude Selection — CheckBestAltitude()

Three altitude levels are computed for each flight:

AltitudePurposeSelection Logic

10.4 Threat Scoring on Routes — ScoreThreatsOnWPLeg()

Samples ScoreThreatFast() at MAP_RATIO intervals along each waypoint leg. Returns worst-point (TT_MAX), sum (TT_TOTAL), or average (TT_AVERAGE).

CheckPathThreats() walks the entire route calling CollectThreatsFast() every 5 km and returns NEED_SEAD and/or NEED_ECM flags — this drives whether escort flights are added.

10.5 ScoreThreatFast() — The Threat Model

Uses pre-computed SamMapData and RadarMapData arrays (not real-time unit queries — this is critical for performance):

10.6 Waypoint Elimination — EliminateExcessWaypoints()

Two-pass cleanup:

  1. Collinearity: If a WP's angle deviation > 10° or < 120° (sharp turn) → keep it; otherwise eliminate
  2. Threat reduction: If the direct path's threat cost ≤ sum of the two sub-legs' costs → eliminate the middle WP (it wasn't helping)

10.7 Timing Calculation — SetWPTimes()

Two-pass algorithm:

  1. Forward pass (target → landing): calculates speeds and arrival times using TimeToArrive(distance, speed). Speed range: 0.7 × CruiseSpeed to 1.3 × MaxSpeed
  2. Backward pass (target → takeoff): calculates departure times to meet the TOT
  3. The TOT waypoint is identified by WPF_TARGET flag, then WPF_TURNPOINT, then first WP
  4. Takeoff, Target, and Assembly points get WPF_TIME_LOCKED
  5. Escort separation applied as MissionData[].separation × CampaignSeconds offset

10.8 Tanker Waypoint Insertion

If fuelNeeded > 2/3 × loaded_fuel → adds an ingress tanker WP. Always tries to add an egress tanker WP. Uses FindNearestActiveTanker() to locate active tanker tracks. Checks fuel reachability with 50% tolerance (fuelNeeded > fuel × 1.5 = unreachable → flight is killed).

11. A* Pathfinding Engine

11.1 Architecture

A singleton ASD (AS_DataClass) with:

  • Priority queue: sorted linked list by f = g + h (cost + heuristic)
  • Closed set (tried): already-expanded nodes
  • Free list (waste): pool of 2000 pre-allocated nodes (zero dynamic allocation)
  • Thread safety: critical sections via AS_THREAD_SAFE

11.2 Algorithm

Standard A* with key modifications:

  • Max 2000 nodes expanded per search (MAX_SEARCH)
  • Max 96 steps path length
  • 8-directional grid movement
  • Partial path on failure: if RETURN_PARTIAL_ON_FAIL flag set, returns the node with lowest heuristic from the explored set
  • Node pooling: Pre-allocated array of 2000 nodes linked as free list; no malloc/new during search

11.3 Air Path Cost Function

For each grid cell neighbor:

  1. Base cost from CostTable[terrain][movement] (air = always 1.0)
  2. Threat sampling: ScoreThreatFast() at cell center + 4 cardinal offsets → take maximum
  3. If max threat > 120 → impassable (no-fly zone)
  4. Otherwise: cost = 1.0 × step + threat / 2.0
  5. Heuristic: distance × 4.0 (strongly encourages direct paths, but threat costs create detours)

13. Ground Tasking Manager (GTM)

While the ATM handles air missions, the GTM handles ground unit assignment in a parallel but structurally similar system:

13.1 Objective Scoring

Each campaign cycle, DoCalculations() scores all objectives:

  • Front proximity: (200 - DistanceToFront) × 0.2, capped at ±30
  • Enemy strength: +1 per 50 enemy vehicles within 100 km of front, capped at 30
  • Priority bonus: +50 if priority > 95, +20 if > 90
  • Combined: front_score + enemy_score + random(5), clamped [0, 100]

13.2 Unit Collection and Assignment

Task() operates in phases:

  1. Collection: Iterates all friendly ground units, filters by team, calls RallyUnit() and UpdateParentStatistics(), assigns to order-type lists based on role scores
  2. Assignment priority varies by action type (Offensive/Defensive/Consolidate):
  • Offensive: Capture(fastest) → Assault(best) → Airborne(best) → Commando(best) → Secure(fastest) → Defend(best) → AirDefense(fastest) → Support → Repair → Radar → Reserve(best)
  • Defensive: Defend(fastest) only
  1. Scoring: Each unit-objective pair is scored considering distance, role match, unit strength, and objective priority

13.3 Interaction with Air Missions

The GTM doesn't directly generate air missions, but ground objective priorities feed into the strategy layer that creates air mission requests. Ground units under attack generate AMIS_CAS requests. Ground objectives targeted by the GTM become targets for AMIS_OCASTRIKE and AMIS_INTSTRIKE.

2. Requests & Messages: Tagged Type Erasure

Current state: Requests are CampRequest structs with a RequestType enum; routing is a chain of switch statements in ProcessRequest(). The VU message system uses integer message IDs with manual dispatch.

Modern approach — std::any with typeid tag dispatch, or a lightweight envelope pattern:


// Tagged message envelope:
class CampaignMessage {
public:
    using Timestamp = std::chrono::steady_clock::time_point;

    template<typename Payload>
    CampaignMessage(Payload&& payload, Priority prio = Priority::Normal)
        : payload_(std::forward<Payload>(payload))
        , typeInfo_(&typeid(Payload))
        , priority_(prio)
        , timestamp_(std::chrono::steady_clock::now())
    {}

    template<typename Payload>
    const Payload* get() const {
        if (*typeInfo_ == typeid(Payload))
            return std::any_cast<Payload>(&payload_);
        return nullptr;
    }

    bool is(const std::type_info& ti) const { return *typeInfo_ == ti; }
    Priority priority() const { return priority_; }
    Timestamp when() const { return timestamp_; }

private:
    std::any            payload_;
    const std::type_info* typeInfo_;
    Priority            priority_;
    Timestamp           timestamp_;
};

// Concrete request types — each is a proper struct, not an enum case:
struct OCARequest {
    ObjectiveID target;
    int priority;
    std::chrono::minutes deadline;
    bool requiresFollowUp;
};

struct BARCAPRequest {
    Waypoint stationPoint;
    float radius;
    int minAircraft;
    std::chrono::minutes onStationTime;
};

struct AirliftRequest {
    UnitID cargoUnit;
    CampaignPoint dest;
    int urgency; // 0-100
};

// Router with double-dispatch or visitor pattern:
class RequestRouter {
public:
    using Handler = std::function<void(const CampaignMessage&)>;

    template<typename PayloadType>
    void on(std::function<void(const PayloadType&)> handler) {
        handlers_[typeid(PayloadType)] = [h = std::move(handler)](const CampaignMessage& msg) {
            if (auto* p = msg.get<PayloadType>())
                h(*p);
        };
    }

    void dispatch(const CampaignMessage& msg) {
        auto it = handlers_.find(*msg.typeInfo_);
        if (it != handlers_.end())
            it->second(msg);
    }

private:
    std::unordered_map<std::type_reference_wrapper, Handler> handlers_;
};

This replaces the monolithic ProcessRequest() switch with a composable routing table. New request types are added by defining a struct + registering a handler — zero changes to existing dispatch code.

Falcon 4 / FreeFalcon Flight Model — Detailed Architecture Breakdown

1. Overall Architecture

The flight model lives in src/sim/airframe/ and is implemented as the AirframeClass. It follows a fixed-order pipeline executed every simulation frame via AirframeClass::Exec(), which runs multiple sub-steps per major frame (SimLibMinorPerMajor iterations) for numerical stability:


for (i = 0; i < SimLibMinorPerMajor; i++) {
    Atmosphere()           ← ISA atmosphere + airspeed
    FlightControlSystem()  ← Gain scheduling + Pitch/Roll/Yaw/Axial
    Aerodynamics()         ← CL, CD, CY lookups + force resolution
    EngineModel(dt)        ← Thrust + fuel + RPM spool
    EquationsOfMotion(dt)  ← Quaternion kinematics + position integration
}
RunLandingGear()           ← Visual gear animation (once per major frame)

The model has two modes: a full 6-DOF model for the player aircraft and a "SuperSimple" model for AI/distant aircraft that bypasses the FCS and directly commands alpha/Nz.

2. Atmosphere Model (atmos.cpp)

Implements a 3-layer ISA (International Standard Atmosphere):

LayerAltitude RangeTemperature Ratio (θ/θ₀)Density Ratio (ρ/ρ₀)
Troposphere0–36,089 ft1 − 6.875×10⁻⁶ × h(θ/θ₀)^4.2559
Lower Stratosphere36,089–65,617 ft0.751865 (constant)0.297076 × e^(0.00004806 × (36089−h))
Upper Stratosphere>65,617 ft0.682457 + h/945374(0.978261 + h/659515)^(−35.16)

From these, it derives:

  • Speed of sound: a = √θ × a_SL (where a_SL = 1116.45 ft/s)
  • Air density: ρ = σ × ρ_SL
  • Dynamic pressure: q̄ = ½ρV²
  • Normalized dynamic pressure: q_som = q̄ × S / m (used throughout the FCS)
  • Mach number from vt / a
  • Calibrated airspeed (CAS) using the isentropic pitot tube equation (separate subsonic/supersonic formulas), with a Newton-Raphson inverse solver (CalcMach) for converting KIAS back to Mach.

3. Aerodynamic Model (aero.cpp)

3.1 Coefficient Lookups

All aerodynamic coefficients are stored as 2D lookup tables indexed by (Mach, α) and loaded from .dat files per aircraft type. The core function uses Math.TwodInterp() for bilinear interpolation:


CL  ← aeroData->clift[Mach × Alpha] × clFactor
CD  ← aeroData->cdrag[Mach × Alpha] × cdFactor
CY  ← aeroData->cy[Mach × Alpha]    × cyFactor

3.2 High-Lift Device Effects

TEF (Trailing Edge Flaps) and LEF (Leading Edge Flaps) modify the effective angle of attack:


tempAlpha = α + tefFactor − lefFactor
  • tefFactor and lefFactor are normalized deflections (current angle / max angle)
  • TEFs increase effective AoA (more camber → more lift), LEFs decrease it
  • The final CL is scaled: CL × (1 + tefFactor × CL_tefFactor)
  • CD is similarly modified by both TEF and LEF factors

3.3 Lift Curve Slope (Numerical Differentiation)

The local lift curve slope CL_α and normal force slope CN_α are computed via central difference at ±2°:


CL_α  = (CL(α+2°) − CL(α−2°)) × 0.25 × TEF_factor
CN_α  = ((CL(α+2°)−CL(α−2°))cos(α) + (CD(α+2°)−CD(α−2°))sin(α)) × 0.25

These derivatives are critical — they drive the pitch FCS gains, trim AoA, and stall detection.

3.4 Ground Effect

Within one wingspan of the ground, lift is boosted up to 13% at 20% span height, linearly fading to zero at full span height. Disabled for AI aircraft.

3.5 Stores Drag

External stores (pylons, tanks, missiles) add drag via the Limiter system: CD_stores = Limiter(mach) × dragIndex.

3.6 Stall Model

Uses the classic formula: `V_stall = 17.16 × √((W/S) /CL)`

When V_cas < V_stall or α > α_critical:

  • Lift is severely reduced: L = min(0, CL × 0.5) × (V_cas / V_stall)
  • An automatic roll command is applied: p_cmd = sin(φ) × 80° × DTR
  • This models the asymmetric lift loss and wing drop at stall

3.7 Force Resolution

Aerodynamic forces are computed in three coordinate systems:


Body axis:      xaero = −D·cos(α) + L·sin(α)
                yaero = CY·q̄·S·(β − |β|·y_shape·0.5)
                zaero = −L·cos(α) − D·sin(α)

Stability axis: xsaero = −D,  zsaero = −L
Wind axis:      xwaero = xsaero·cos(β) + ysaero·sin(β)

4. Flight Control System (FCS)

4.1 Top-Level Dispatcher (fcs.cpp)

FlightControlSystem() runs in this order:

  1. Damper scheduling — pitch/yaw and roll damping factors via Q̄-dependent limiter tables
  2. Gains() — compute all control law gains (see §4.4)
  3. SetStallConditions() — evaluate stall state machine
  4. Pitch(), Roll(), Yaw(), Axial() — axis control laws

4.2 Gain Scheduling (gain.cpp)

The heart of the FCS. Computes time-varying gains based on current flight conditions:

AOA Bias (1G trim):


α_bias = [g·cos(γ)·cos(μ) / q_som + 0.1·gear − CL₀·TEF_factor] / CL_α,0 − tefFactor + lefFactor

Command Mode Selection:

  • If α_max × CL_α × q_som / g > max_G → G-command mode (Nz control)
  • Otherwise → AOA-command mode (direct alpha control)

Pitch Axis — Second-Order Control Law:

  • Computes a "Fitch theta-2" time constant: t_θ₂ = V / (g × Nz_α) (Nz per radian alpha)
  • Solves a quadratic characteristic equation for the closed-loop poles, yielding two time constants tp02, tp03
  • Forward path gain: kp05 = tp02 × tp03 × ω² (or with the g/(q̄·S·CN_α) factor in Nz mode)
  • Landing gear modifies gains via pitchGearGain

Roll Axis:

  • Time constant tr01 is Q̄-scheduled (0.416s at 100 psf → 0.25s at 250+ psf)
  • Max roll rate from 2D table: kr01 = TwodInterp(α, q̄, rollTable) × DTR
  • Coupling term: kr02 = cos(α)

Yaw Axis:

  • Damping ratio zy01 = 0.70, bandwidth coupled to roll: ωy = 0.3 / tr01
  • Same quadratic pole-placement structure as pitch

4.3 Pitch Control (pitch.cpp)

Two paths based on command mode:

AOA Command Mode (F-16 style — stick position → desired alpha):


max_α_cmd = α + (G_max − CL·q_som/g − cos(μ)·cos(γ)) × g / (q_som × CN_α)

Chain of limiters: Cat III AOA → Positive G → AOA → Negative G

Nz Command Mode (stick → desired G-load):


error = (p_stick × G_available − (Nz − cos(μ)·cos(γ) − gear_correction)) × kp05

Both modes use a PI controller with Adams-Bashforth integration:


e_prop = kp02 × error
e_intg = FIAdamsBash(kp03 × error, dt, history)   ← 4-point Adams-Bashforth
α_cmd = e_prop + e_intg

Alpha integration uses a 7-term Tustin (bilinear) integrator for numerical stability:


α = F7Tust(α_cmd, τ_pitch × pitchMomentum, dt, history)

Stall recovery overrides force specific alpha commands: ±60° in deep stall with oscillating timers, blended recovery toward saved trim state.

4.4 Roll Control (roll.cpp)

Rate-command system with alpha-dependent limiting:


p_cmd = r_stick × kr01                          ← stick → rate command
p_cmd *= RollRateLimiter(α − α_error)           ← alpha-dependent table
p_cmd *= min(V_cas / V_switch, 1.0)             ← speed reduction below 220 KCAS
p_cmd × 0.5 if gear down                         ← gear reduction
The alpha-error term couples body rates into the limiter: `α_error = (q/2+p) × 0.1 × RTD`, effectively reducing the available roll rate at high AoA when the aircraft is already rotating.

Closed-loop response via first-order lag:


p_stable = FLTust(p_cmd, tr01 × rollMomentum, dt, history)

Roll angle limiting drives the command back toward maxRoll if exceeded. Asymmetric thrust from twin engines adds: (thrust_L − thrust_R) × 0.05.

4.5 Yaw Control (yaw.cpp)

PI controller on lateral acceleration error:


Ny_cmd = y_stick × 2.0                          ← rudder pedals → Ny command (±2g max)
Ny_cmd ×= min(q_som × β_max × 0.05 / g, 1.0)  ← Q̄ availability scaling
Ny_cmd ×= AlphaLimiter(α)                       ← alpha-dependent
Ny_cmd ×= RollRateLimiter(|p|)                  ← roll-rate limiting
Ny_cmd ×= 5.0 / Limiter(V_cas × 0.8)           ← speed normalization
Ny_cmd ×= Limiter((350 − V_cas) × 0.2)          ← high-speed yaw damping

error = (Ny_cmd + Ny_cg_offset) × ky05
β_cmd = clamp(ky02 × error + AdamsBash(ky03 × error), β_min, β_max) × yl_sdamp

Anti-windup clamps the integrator and resets history when beta limits are hit.

Beta integration is a first-order lag: β = FLTust(β_cmd, ty02 × yawMomentum, dt, history).

Asymmetric thrust adds: (thrust_R − thrust_L) × 1.5 to the beta command.

4.6 Axial Control (axial.cpp)

Manages actuator dynamics for speed brake, gear, and tail hook (simple first-order position models: pos += 0.3 × dt × cmd).

Thrust effectiveness computation:


nozzle_area = 1.0 − throttle_reverse
effective_thrust = nozzle_area − throttle_reverse × 0.8666

Over-speed gear damage: if q̄ > maxQ̄ (300–350 psf), a probabilistic damage model triggers gear structural failure.

5. Engine Model (engine.cpp)

5.1 Thrust Computation

Thrust is 2D-interpolated from (Altitude × Mach) tables for three power settings:


Thrust = TwodInterp(alt, mach, table[power_setting])
Throttle PositionPower SettingTable Index
0.0 (Idle)Idle[0]
1.0 (MIL)Military[1]
1.0+ (AB)Afterburner[2]

Interpolation:

  • MIL power: T = ((T_MIL − T_idle) × PL + T_idle) / mass
  • Afterburner: T = (2 × (T_AB − T_MIL) × (PL − 1.0) + T_MIL) / mass

5.2 RPM Spool Model

First-order lag with altitude/Mach correction:


RPM_cmd = 0.7 + 0.3 × PL (MIL)  or  1.0 + 0.06 × (PL − 1.0) (AB)
spool_rate_adj = spool_rate + (−alt/25000) + (−mach/2)
RPM = FLTust(RPM_cmd, spool_rate_adj, dt, history)

Engine states: Stopped → Off → Running, with JFS start sequences, windmilling RPM (KIAS/450 × 0.12), and flameout handling.

5.3 Engine-Specific RPM Corrections

Different engines have unique RPM schedules:

  • PW-100/220: Idle RPM ramps with Mach (0.84–1.4M), altitude adds (alt/10000)/30 + 0.7
  • PW-229/GE-129: Reduced speed excursion zone at 0.55–1.1M, probabilistic AB lighting
  • F-14 TF30: RPM spools to 0.85 when α > 18° and M < 0.9 (stall prevention)

5.4 Fuel System

Multi-tank fuel model with priority-based consumption, tank-to-tank transfer rates, external drop tank jettison, and fuel state tracking (internal vs. external). Fuel flow is either table-interpolated or proportional to thrust.

6. Equations of Motion (eom.cpp)

6.1 Orientation Update

Quaternion kinematics — the orientation is stored as a quaternion (e1, e2, e3, e4) and updated each timestep via CalcBodyRates(dt) and CalcBodyOrientation(dt), followed by trigonometric extraction of Euler angles (Trigenometry()).

6.2 Velocity Equation


V̇_tangential = x_aero + x_prop − g·sin(γ)

The net acceleration drives the true airspeed vt via CalculateVt(dt).

6.3 Position Integration

Earth-frame velocities account for wind:


ẋ = vt·cos(γ)·cos(σ) + wind_x
ẏ = vt·cos(γ)·sin(σ) + wind_y
ż = −vt·sin(γ)

Position is updated with Euler integration: x += ẋ × dt.

6.4 Ground Model

Ground contact uses spring-damper dynamics with SetGroundPosition():

  • Clamps aircraft to terrain surface
  • Gear spring compression model
  • Ground friction via CalcMuFric(): surface-type-dependent (dry/wet/crosswind), brake-state-dependent (parking/analog/digital/wheel brakes), carrier arrest

Takeoff detection: triggers when q̄·CN_α > 0.55 (enough aerodynamic authority) and vertical velocity is positive.

Landing impact: discriminated by nose angle and impact angle. Successful landing vs. crash/bounce is determined by threshold comparisons, with ATC notification on success.

6.5 Stall State Machine

Defined in airframe.cpp::SetStallConditions():


None → EnteringDeepStall → DeepStall → Spinning → FlatSpin
                                       ↓
                                   Recovering → None
Trigger conditions are weight/asymmetry-dependent (e.g., `α > 31° − 9×(W/W_empty − 1.3) − 10×asymmetry/W`), meaning loaded aircraft with asymmetric stores stall earlier.

7. Data Pipeline (readin.cpp)

All aircraft-specific data is loaded from .dat files at startup:


actypes.lst → list of aircraft types
For each type:
  acdata/<name>.dat →
    Scalar params: weight, area, fuel, α/β limits, G-limits, gear geometry, CG, span
    AeroData:     CL[Mach×α], CD[Mach×α], CY[Mach×α] + scaling factors
    EngineData:   Thrust[3×Alt×Mach], FuelFlow[3×Alt×Mach], AB flag
    RollData:     MaxRollRate[α×q̄]
    AuxAeroData:  ~500 fields (spool rates, flap params, fuel tanks, TFR gains, sounds, animations)
    Limiters:     Q̄-dependent limiter tables (AOA, G, roll rate, damping)

8. Simplified Model (supersimple.cpp)

AI aircraft use a drastically simplified FCS:

  • Roll: first-order lag on stick command (p = 0.75·stick·300° + 0.26·p_prev)
  • Pitch: direct Nz = cos(γ)·cos(φ) + stick·G_available, then α = Nz·g / (q_som·CN_α)
  • Drag reduction: uses 75% of true α for drag lookup (less speed bleed in dogfights)
  • Includes P_subS (specific excess power) and SustainedGs (max sustained G via iterative α search) for AI energy management

9. Trim Solver (trim.cpp)

Finds steady-state (α, throttle) at startup via Newton's method iteration:

  • Solves acc_z = z_aero + z_prop + g → 0 (vertical equilibrium) for α
  • Solves acc_x = x_aero + x_prop → 0 (longitudinal equilibrium) for throttle
  • Up to 13 iterations per axis, with speed adjustment if trim fails

10. Turbulence Model (turbulence.cpp)

Multi-source probabilistic turbulence:

  • Mechanical (low altitude, wind-proportional): amplitude = wind × 0.1
  • Thermal (water/urban, daytime only): up to 5.0 amplitude
  • Cloud convection (near cumulus cells within 18,400 ft): up to 1.0
  • Tropopause (FL350–FL360): amplitude 2.0
  • Night reduces all amplitudes; poor weather adds continuous stratus turbulence
  • Output smoothed by 1st-order low-pass filter (FLTust, τ = 1.0s for vertical, 5.0s for roll)

1. Stall State Machine: enum switch → std::variant + std::visit

This is the single biggest win. The stall mode is an enum with switches scattered across pitch.cpp, roll.cpp, yaw.cpp, eom.cpp, and airframe.cpp. Each switch has to know about every state.

Before (scattered across ~5 files):


// airframe.h

    case EnteringDeepStall: aoacmd = 60.0F*DTR*sign + 5.0F*DTR*pshape; break;
    case DeepStall:         aoacmd = oscTimer*stallMag*(0.3F-fabs(r))*3.3F; break;
    case Spinning:         aoacmd = ±60.0F*DTR based on roll; break;
    case FlatSpin:         aoacmd = 0; break;
    case Recovering:       aoacmd = lerp towards saved trim; break;
    case None:

}

// roll.cpp — duplicated switch

    case DeepStall:         pscmd = sin(phi)*±5*DTR + osc; break;

}

After — each state is a type with its own behavior:

        return aoacmd;  // pass through — normal FCS

    float oscillationTimer;

// ... FlatSpin, Recovering, EnteringDeepStall similarly

    StallNone, EnteringDeepStall, DeepStall, Spinning, FlatSpin, Recovering
>;

// Usage in pitch.cpp — no switch needed:
struct PitchVisitor {

// table2d.hpp
template<typename T>
class Table2D {
public:
    Table2D(std::vector<float> rowKeys, std::vector<float> colKeys,
            std::vector<T> values)
        : rowKeys_(std::move(rowKeys))
        , colKeys_(std::move(colKeys))
        , values_(std::move(values))
    {
        assert(rowKeys_.size() * colKeys_.size() == values_.size());
    }

    // Bilinear interpolation with clamping at boundaries
    T interpolate(float rowKey, float colKey) const {
        auto [r0, r1, rf] = findBracket(rowKeys_, rowKey);
        auto [c0, c1, cf] = findBracket(colKeys_, colKey);

        T v00 = at(r0, c0), v10 = at(r1, c0);
        T v01 = at(r0, c1), v11 = at(r1, c1);

        return v00*(1-rf)*(1-cf) + v10*rf*(1-cf)
             + v01*(1-rf)*cf     + v11*rf*cf;
    }

    // Central-difference numerical derivative along column axis
    T dByCol(float rowKey, float colKey, float delta = 2.0f) const {
        return (interpolate(rowKey, colKey + delta)
              - interpolate(rowKey, colKey - delta)) / (2.0f * delta);
    }

    size_t numRows() const { return rowKeys_.size(); }
    size_t numCols() const { return colKeys_.size(); }

private:
    std::vector<float> rowKeys_;  // e.g., Mach breakpoints
    std::vector<float> colKeys_;  // e.g., Alpha breakpoints
    std::vector<T> values_;       // row-major: values_[r * numCols + c]

    T at(size_t r, size_t c) const { return values_[r * colKeys_.size() + c]; }

    struct Bracket { size_t lo, hi; float frac; };
    Bracket findBracket(const std::vector<float>& keys, float key) const {
        auto hi = std::upper_bound(keys.begin(), keys.end(), key);
        if (hi == keys.begin()) return {0, 0, 0.0f};
        if (hi == keys.end())   return {keys.size()-2, keys.size()-1, 1.0f};
        auto lo = std::prev(hi);
        float frac = (key - *lo) / (*hi - *lo);
        return {static_cast<size_t>(lo - keys.begin()),
                static_cast<size_t>(hi - keys.begin()), frac};
    }
};

// aero_data.hpp — clean, no raw pointers
struct AeroData {
    Table2D<float> cl;   // CL(Mach, Alpha)
    Table2D<float> cd;   // CD(Mach, Alpha)
    Table2D<float> cy;   // CY(Mach, Alpha)
    float clFactor{1.0f}, cdFactor{1.0f}, cyFactor{1.0f};

    // Convenience
    float clAlpha(float mach, float alpha) const {
        return cl.dByCol(mach, alpha, 2.0f) * clFactor;
    }
};

// aero.cpp — usage is now self-documenting and bounds-safe

using SimStep = std::function<void(float dt)>;

class SimulationPipeline {
public:
    void addStep(std::string name, SimStep step) {
        steps_.push_back({std::move(name), std::move(step)});
    }

    void run(float dt, int substeps) {
        for (int i = 0; i < substeps; ++i) {
            for (auto& [name, step] : steps_) {
                auto t0 = std::chrono::high_resolution_clock::now();
                step(dt);
                auto t1 = std::chrono::high_resolution_clock::now();
                // Optional: profile timing per step
                profile_[name] += std::chrono::duration<double>(t1-t0).count();
            }
        }
    }

private:
    std::vector<std::pair<std::string, SimStep>> steps_;
    std::unordered_map<std::string, double> profile_;
};

// Construction — order is explicit and data-driven
SimulationPipeline buildPipeline(Airframe& af) {
    SimulationPipeline pipeline;
    pipeline.addStep("atmosphere",  [&af](float dt) { af.atmos().update(dt); });
    pipeline.addStep("fcs",        [&af](float dt) { af.fcs().update(dt); });
    pipeline.addStep("aero",       [&af](float dt) { af.aero().update(dt); });
    pipeline.addStep("engine",     [&af](float dt) { af.engine().update(dt); });
    pipeline.addStep("failure",    [&af](float dt) { af.failures().update(dt); });
    pipeline.addStep("flaps",      [&af](float dt) { af.flaps().update(dt); });
    pipeline.addStep("eom",        [&af](float dt) { af.eom().update(dt); });
    return pipeline;
}

// integrators.hpp
class FirstOrderLag {
    // Replaces FLTust
public:
    float update(float command, float timeConstant, float dt) {
        // τ·dy/dt + y = cmd  →  y(n+1) = y(n) + (cmd - y(n))·dt/τ
        float alpha = dt / (timeConstant + dt);
        state_ = state_ + alpha * (command - state_);
        return state_;
    }
private:
    float state_{0.0f};
};

class BilinearIntegrator {
    // Replaces F7Tust (7-term Tustin)
    // The 7-term version is a Tustin transform with pre-warping
    // and multiple poles — can be modeled as a cascaded biquad
public:
    BilinearIntegrator(float b0, float b1, float a1, float a2)
        : b0_(b0), b1_(b1), a1_(a1), a2_(a2) {}

    float update(float input, float dt) {
        float output = b0_ * input + b1_ * x1_ - a1_ * y1_ - a2_ * y2_;
        x1_ = input;
        y2_ = y1_;
        y1_ = output;
        return output;
    }
private:
    float b0_, b1_, a1_, a2_;
    float x1_{0}, y1_{0}, y2_{0};
};

class AdamsBashforth4 {
    // Replaces FIAdamsBash (4-point Adams-Bashforth)
public:
    float update(float input, float dt) {
        float output = history_[0]
            + dt * (55.0f/24.0f * input
                   - 59.0f/24.0f * history_[1]
                   + 37.0f/24.0f * history_[2]
                   - 9.0f/24.0f  * history_[3]);
        history_[3] = history_[2];
        history_[2] = history_[1];
        history_[1] = history_[0];
        history_[0] = output;
        return output;
    }
private:
    std::array<float, 4> history_{};
};

// Usage in pitch axis:
class PitchAxis {
    BilinearIntegrator alphaFilter_;
    AdamsBashforth4    integralFilter_;
    FirstOrderLag      rateLimiter_;

public:
    void update(float aoacmd, float dt) {
        alpha_ = alphaFilter_.update(aoacmd, dt);
        integral_ = integralFilter_.update(integralCmd_, dt);

    void set(std::string name, Table1D table) {
        limiters_[std::move(name)] = std::move(table);
    }

    std::optional<float> limit(std::string_view name, float x) const {
        auto it = limiters_.find(name);
        if (it == limiters_.end()) return std::nullopt;
        return it->second.interpolate(x);
    }

    float limitOr(std::string_view name, float x, float defaultVal = 1.0f) const {
        return limit(name, x).value_or(defaultVal);
    }

private:
    std::unordered_map<std::string, Table1D> limiters_;
};

1.2 Integration with the Simulation Loop

The AI is driven by DigitalBrain::FrameExec() (digimain.cpp:566), called every simulation frame:

  1. Clamp controls (pStick, rStick, throtl, yPedal to [-1,1] or [0,1.5])
  2. If fuel <= 0 AND speed < minVcas → Eject()
  3. Gear up check after takeoff waypoint
  4. Clear MslFireFlag | GunFireFlag
  5. CheckLead() — verify leader alive, promote if needed
  6. Set target update rate (5 sec default, 0.01 sec for Combat AP)
  7. DoTargeting() — sensor fusion + target list update
  8. SetCurrentTactic() → DecisionLogic() — the decision brain
  9. Actions() — dispatch to mode-specific action handler

  12. Clamp controls to valid ranges
  13. If |rStick| > 0.9 and !groundAvoidNeeded → pStick = 0 (unload for roll rate)
  14. No AB if SaidFumes, SaidFlameout, or on ground (non-takeoff)

9.3 Altitude/Heading/Speed Control

PID Controller (autopilot.cpp:242):


PIDLoop(error, K, KD, KI, Ts, *lastErr, *MX, Output_Top, Output_Bottom, LimitMX):
  MP = K * error                    // Proportional
  MD = KD / Ts * (error - lastErr) // Derivative
  MX += KI * Ts * error           // Integral (accumulator)
  Output = MP + MD + MX
  
  // Clamp output
  if (Output > Output_Top): Output = Output_Top
  if (Output < Output_Bottom): Output = Output_Bottom
  
  // Anti-windup
  if (LimitMX): MX = Output - MP - MD
  
  lastErr = error
  return Output

13.1 Detection

CollisionCheck (digi_cavoid.cpp:12):


CONSTANTS:
  hRange = 200 ft (miss distance)
  hRangeSq = 40000
  reactFact = 0.55
  GS_LIMIT = 9.0G

reactTime = (GS_LIMIT / maxGs) * reactFact
  // Example: maxGs=9 → reactTime = 0.55 sec
  //          maxGs=4 → reactTime = 1.24 sec

timeToImpact = (range - hRange) / -rangedot
if (timeToImpact > reactTime AND range > hRange):
  return  // no collision

// Linear extrapolation check
for dt = 0.05 to reactTime step 0.1:
  predict self position: (x+dx*dt, y+dy*dt, z+dz*dt)
  predict target position similarly
  if distance < hRange: collision = TRUE
  if range starts diverging: break

if collision:
  Set escape point 45° azimuth, 45° elevation, opposite to target roll
  range = 10000 ft
  AddMode(CollisionAvoidMode)
